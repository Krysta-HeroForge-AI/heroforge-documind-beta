## 🎓 Key Concepts

### Overlap Percentage

**Definition**: Percentage of activities and components that appear in both demo and workshop

**Interpretation**:
- **>80% (High)**: Almost identical content - strong pre-build candidate
- **50-80% (Moderate)**: Significant duplication - pre-build recommended
- **<50% (Low)**: Complementary content - can live-code

### Pre-Build Strategy

**Definition**: Building session features ahead of time instead of live-coding during demo

**Benefits**:
- No Claude Code wait times
- Professional, polished demos
- More time for explanation and Q&A
- Working reference for students

**Cost**: Time investment upfront (4-6 hours per session)

### Show-and-Explain Approach

**Definition**: Checkout pre-built code, walk through explaining design decisions instead of typing

**Steps**:
1. Checkout `session-X-complete` branch
2. Explain what was built and why
3. Walk through key code sections
4. Run the working system
5. Answer questions

**Time**: Fits comfortably in 35-minute demo slot

### Branch Strategy

**Definition**: Git workflow for organizing pre-built demos and student checkpoints

**Structure**:
- `session-X-complete`: Instructor's finished demo
- `session-X-start`: Student's workshop starting point
- `session-(X+1)-start` often equals `session-X-complete`
